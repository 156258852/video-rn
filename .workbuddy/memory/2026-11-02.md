## 桥接方式讨论：能否用 NativeModule 代替 ViewManager
- 主人问「是否可以用 requireModule 的方式」。
- 结论：播放器**必须有 view**，纯 NativeModule 不能渲染 UI；可行的是「ViewManager 渲染 + NativeModule 出命令 + RCTEventEmitter 出事件」的混合式。
- 现状 ViewManager 方案（RCT_EXPORT_VIEW_PROPERTY + dispatchViewManagerCommand + RCTBubblingEventBlock）对 demo 够用，暂不改造；未来若上新架构（Fabric/TurboModule），dispatchViewManagerCommand 需换 Fabric command，NativeModule 需写 codegen spec，到时一次性迁移。
- 迁移成本边界：原生 450 行里只有 Manager.m 的 45 行 + .h 属性声明与桥接相关，AVQueuePlayer/时长 offsets/全局时间换算/跨段重建队列全是纯 AVFoundation，换架构零改动；JS 侧 usePlaylistPlayback 只认 duration/currentTime/seek，也不用动。

## run-ios.sh 的 mktemp 坑
- `yarn ios:install` 报 `mktemp: mkstemp failed on /tmp/rnbuild.XXXXXX.log: File exists`。
- 原因：mktemp 模板**必须以 XXXXXX 结尾**，`.log` 放在 X 后面时 macOS BSD mktemp 直接失败（且 /tmp 里有字面量 `rnbuild.XXXXXX.log` 的旧残留，已 rm）。
- 修复：scripts/run-ios.sh:26 改为 `LOG="/tmp/rnbuild-$(date +%Y%m%d-%H%M%S).log"`，不再依赖 mktemp。`bash -n` 通过。
